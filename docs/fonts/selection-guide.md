# 字体选型指南（新增主题）

> 适用范围：为 `src/designs/<id>/` 新增或替换主题字体时的完整流程与记录要求。强制条款在 `docs/rules/visual-language.md`「字体（Typography & Fonts）」节，本文件是其展开流程与工具契约。
>
> **本文件不含任何本机字体清单**——个人字体文件、扫描结果与候选目检记录只存于被忽略的 `.local-fonts/`（本机工作台），不得写入公开文档。

## 0. 总原则

1. **先隐喻，后字体**：从设计隐喻与信息结构出发（这个界面模拟什么物件、给谁看、信息如何组织），先确定字体要承担的**角色与气质**，再去找具体字体。**不得**从主题色、审美形容词或"看起来专业"出发挑字；**不得**为了显得专业机械增加字体数量——一个主题可以只用一种字体，也允许多字体组合。
2. **测量 + 目检双轨**：字符覆盖、字重、可变轴、体积等结论以**完整 cmap 映射实测**（扫描清单）为准；风格与气质以**真实字体文件渲染的样张目检**为准。**任何候选都不得仅凭字体名或元数据定案**——名称含 `CJK / Japanese / Sans` 等词不代表实际覆盖，最终分类必须结合样张视觉检查。
3. **本地 ≠ 生产**：本地字体库只用于发现与预览，不是生产依赖、不是静态资源目录；进入生产必须过**许可闸门**并走既有注册管线（见 §4 / §5）。
4. **字体不替代设计**：字体选择不能取代对页面布局、信息架构与交互方式的独立设计。

## 1. 流程（五步）

### 步骤 1 · 明确设计隐喻与字体角色

先回答：这个主题模拟什么物件或媒介？它的信息结构是什么（谁是标题、谁是正文、数字/编号是否承担对齐职责、有没有状态/刻度类的技术标记）？

由此导出字体需要表达的特征，例如：

- "针式打印机的机械感" → 点阵感、等宽数字、字面紧致；
- "档案卡片的秩序感" → 阅读型衬线正文 + 清晰编号；
- "广播面板的工程感" → 技术等宽标签 + 刻度数字。

**产出（必进记录）**：设计隐喻，以及标题 / 正文 / 数字·技术标记三类角色的分配草案。

### 步骤 2 · 在本地字体库中发现候选

- **唯一入口**：`.local-fonts/library/`（Windows 目录联接）。不要直接访问系统字体目录，也不要每次重新猜测外部路径。
- **唯一工具**：`.local-fonts/tools/scan-fonts.mjs`（可重复运行），产出 `.local-fonts/font-catalog.json`。重扫一条命令：`node .local-fonts/tools/scan-fonts.mjs`。
- 初筛可以借**关键词与测量**（覆盖统计、等宽实测、容器格式），但关键词只用于**检索**、不用于**定级**——最终分类必须经步骤 3 目检。

### 步骤 3 · 样张目检（不可跳过）

- 启动：`node .local-fonts/tools/specimen-server.mjs` → 打开 `http://127.0.0.1:8794/`。
- 并排对比最多 6 个 face（`?sel=<id>,<id>` 可复现组合）。
- **必看项**：大标题 / 正文 / 按钮·标签 / 数字·编号 / 常用标点 / 字重（可变字体拖动轴值）/ **缺字回退**（两段同文对照：本字体栈 vs 纯系统回退栈）。
- 像素、点阵、低分辨率类字体：以**接近其设计尺寸的小字号**验证实际可读性与网格一致性；必要时在目标页面的真实版式里再看一遍。
- 记录目检结论：哪些候选被排除、原因是什么（气质不符 / 笔画冲突 / 灰度太重 / 缺字过多）。

### 步骤 4 · 许可闸门

只有**确认允许网站嵌入与再分发**的字体才能进入正式字体资源管线。判据顺序：

1. 字体文件内嵌字段（清单中的 `license` 与 `embedding.fsType`）——**线索**；
2. 字体自带许可文件或厂商官方许可页面——**以此为准**；
3. 仍无法确认 → **不可用**，只能停留在本地候选。

注意："未声明 ≠ 不可用、已声明 ≠ 可以直接嵌入或再分发"，两者都需要人工核实。需要保留声明的字体，随该设计附 `SOURCE-LICENSE.txt`（汇编为逐来源许可合集；provenance 规则同 `design.json` 既有约束）。

### 步骤 5 · 生产接线与记录

- **人工边界**：只把确定启用的 family 写入 `fonts.config.json`（id、注册名、CSS 变量、目录回退元数据；确需保持历史注册行为时使用最小 `variantOverrides`）。这些回退字段只用于目录映射校验，不会写进浏览器 `--font-*`；字体仓新增 family 不会自动进入站点。
- **外部目录接线**：`npm run fonts:update -- --catalog-url <固定 catalog URL> --catalog-sha256 <发布页 SHA>` 验证目录 schema、family package、许可与哈希，生成 `fonts.lock.json`、`fonts.catalog.json` 和 `src/fonts/generated.ts`。首次采用 / 升级必须从发布页带外取得 SHA，不允许自动追 latest。
- **本地准备**：`npm run fonts:prepare` 只下载锁定的启用 family，验证外层包与包内逐文件哈希后安装到被忽略的 `.cache/fonts/`；已有完整缓存只复核不重下。`npm run fonts:check` 完全离线。
- **Astro 接线**：`astro.config.mjs` 展开生成定义接入 `fontProviders.local()` → 页面内 `<Font cssVariable ...>`（`astro:assets`）→ 该设计 `style.css` 用 `@theme inline` 注册进 Tailwind。所有 npm / local registration 必须 `fallbacks: []` + `optimizedFallbacks: false`，`--font-*` 只能暴露主 face。不得在 `astro.config.mjs` 手工列 CJK 分片，也不得手改生成文件。
- **构建期裁剪与外置**：`astro build` 之后由 `fonts:prune` 按最终产物文本逐页裁剪 `@font-face` 并把保留规则外置为 `dist/_astro/fonts-<hash>.css`（字体族相同的页面共用一个包）。这一步只做**整分片取舍**，不打开、不改写、不重新子集化任何字体字节，因此不触发 OFL Reserved Font Name 的"修改字体"问题。体积上限 15 MiB 是硬门禁，超限应减少重复 HTML / 字体 CSS，不得放宽阈值。规则见 `../rules/operations.md`「字体裁剪与体积门禁」（决策见 `../adr/0013-build-time-font-shard-pruning.md`）。
- **npm provider**：仍需 Fontsource 包的 6 个 family 保持 `remote: false`、关闭 `optimizedFallbacks`，并由 `localNpmProvider()` 把 provider 返回的包 URL 映射回已安装 `node_modules`。`remote: false` 本身仍会产出 jsdelivr URL，不能据此宣称离线。
- **设计 CSS 拥有完整回退栈**：每个使用 `var(--font-*)` 的 `font` / `font-family` 必须以显式 fallback 收尾；承诺 CJK 的字体栈必须把 Zhuque / LXGW / Ark Pixel 放在系统中文之前。设计一旦选用 core-cjk，其正式页与预览的每个字体变量栈都要带该核心变量，避免局部微标签在新增 CJK 文案时落回系统字体。顺序见 §4，`npm run fonts:typography` 是自动门禁。
- **六项记录写入位置**：
  - 自产（`self-produced`）与复刻（`third-party-analysis`）→ 该设计 `DESIGN.md` 的字体章节；
  - 厂商来源（`official-vendor` / `official-docs-derived`）→ 该主题 `docs/designs/<id>/ADAPTATION.md`（`DESIGN.md` 只读，不得改写）。

**六项记录模板**（每次选型必填）：

1. 设计隐喻，以及字体需要表达的特征；
2. 标题、正文、数字 / 技术标记分别使用什么字体；
3. 为什么选中该字体，而不是其他候选；
4. 简体中文、日文、英文的**实际覆盖**（以清单的 GB2312 / 假名 / ASCII 数字为准）及回退方案；
5. 字重、可变轴、资源体积和许可证是否合适；
6. 目标字体缺失时的**回退顺序**。

## 2. 选型维度（候选方向，非固定规则）

下表把常见拟物隐喻映射到"字体需表达的特征"与"样张里要检查什么"。**它是检索与检查的提示，不是按字体名称自动分配的固定规则**；具体分类以样张口检为准。

| 方向 | 字体需表达的特征（从隐喻导出） | 样张重点检查 | 常见角色分配 |
|---|---|---|---|
| 打印机 / 小票机 | 打字机、窄体、点阵感、等宽数字 | 数字与编号的等宽对齐、字面密度、小字号锐度 | 单一等宽/点阵声部；数字必须等宽 |
| 档案卡 / 图书馆 | 打字机、阅读型衬线、档案编号 | 长篇阅读灰度、编号与字段标签的清晰度 | 阅读型衬线正文 + 编号/标签用等宽或打字机体 |
| 收音机 / 工业仪表 | 技术等宽、刻度数字、清晰的状态标记 | 刻度数字、小号状态标签、方硬骨架 | 技术等宽标签 + 中性无衬线正文 |
| 复古印刷 / 说明书 | 衬线、旧式印刷、窄体标题与正文搭配 | 标题密度、旧式笔形与粗细对比 | 窄体或展示型衬线标题 + 阅读型衬线正文 |
| 像素设备 / 低分辨率终端 | 像素或低分辨率风格 | **实际显示效果**：设计尺寸小字号下的可读性、网格一致性 | 全站像素单声部（标题=正文）；慎配常规字体混排 |
| 手写 / 艺术化 | 手写或装饰 | **仅适量展示**：落款、标题点缀；长篇正文不得牺牲可读性 | 手写体仅用于少量展示位，正文另配可读字体 |

**通用检查点**（任何方向都适用）：数字是否等宽 / 表格数字；全角与半角标点的观感；中英混排灰度是否均匀；小字号是否可读；缺字回退在目标语言下是否可见、是否可接受。

## 2.5 在线来源（补充通道）

本地字体库不能满足设计意图时，可以扩展调研**在线开源来源**（不限于 Google Fonts）。规则：

- **来源不限、核验从紧**：每个候选必须定位到**具体字体家族 / 项目 / 许可文件 / 可下载文件**（以官方页面或官方仓库为据；第三方聚合目录只作发现渠道）。不得因站名含 "Free / Open / Fonts" 就假定可自由再分发。
- **先核验、后下载**：下载前确认官方许可——OFL 逐项检查完整文本、版权声明与 **Reserved Font Name（RFN）** 行；Apache-2.0 / CC0 等分别核实义务。未核验许可的文件**不得下载、不得预览、不得进入任何候选复制**。
- **存放与伴生**：下载件存 `.local-fonts/online-candidates/<source>/<family>/`，**许可文件与字体同目录保留**；候选清单 `.local-fonts/online-font-candidates.json`（来源页 / 真实下载地址 / 许可 / 实测覆盖 / 分发方案 / 状态），与本地扫描清单分离维护。
- **同一套验证**：下载件用**同一扫描器**实测覆盖与可变轴，并用**同一 UI 的第二个实例**做浏览器样张（`--port 8795 --catalog .local-fonts/online-font-catalog.json`）。
- **CJK 体积纪律**：优先官方子集 / 分片分发。需要进入生产目录的完整 CJK 源字体必须先由外部字体仓生成带 `unicode-range` 的核心分片包，并记录源文件、分片哈希、覆盖范围与许可；不得把 8MB+ 单体 CJK 字体直接塞进页面，也不得在运行时或资料变更时重新子集化。
- **状态口径**：`downloaded-verified` / `documented-not-downloaded` / `research-only`（许可未核验）/ `excluded`——只有前两者可进入后续选型对比，后两者不得进入生产管线。

## 3. 本地工作台（工具契约）

目录布局（`.local-fonts/` 已被 `.gitignore` 的 `.*/` 规则排除，**不要重复添加忽略规则**）：

```
.local-fonts/
├─ library/                  # 字体库入口（Windows 目录联接；唯一默认扫描入口）
├─ font-catalog.json         # 扫描清单（个人数据，不入库、不进构建）
├─ font-catalog.summary.md   # 人读摘要
├─ tools/                    # 可重复运行的工具
│  ├─ scan-fonts.mjs         # 扫描器
│  ├─ specimen-server.mjs    # 样张服务器
│  ├─ specimen/              # 样张 UI（html/css/js）
│  └─ lib/                   # sfnt 拆包 / 参考字符集
└─ README.md                 # 本机工作台说明
```

- **扫描器**：`node .local-fonts/tools/scan-fonts.mjs [--library <dir>] [--out <json>] [--match <子串>] [--limit N] [--no-hash]`。
- **零新增依赖**：深解析复用 Astro 字体工具链自带的 `fontkitten` / `fontace`（随 `npm ci` 安装，MIT）；TTC 拆 face 与表目录读取为本地自实现（`tools/lib/sfnt.mjs`）。两者缺失时脚本会明确报错（先执行 `npm ci`），**不得**为此向项目添加任何新依赖。
- **覆盖口径（完整 cmap，非抽样）**：逐字符枚举 + 非零字形校验；参考集为 GB2312（6763 字）、JIS X 0208 行映射（Shift_JIS 可解码集）、假名、ASCII、Latin-1 字母、全角、常用标点。**参考集覆盖 ≠ "完整 CJK 支持"结论**：日文字体可以覆盖大量共享汉字，这不等于它是为简体排印设计的——结合目检定案。
- **样张服务器**：`node .local-fonts/tools/specimen-server.mjs [--port 8794]`，只绑定 `127.0.0.1`；按 face 实时读取真实字体文件字节（`.ttc` 集合按 face 重打包后提供给浏览器）；**不复制字体文件、不参与构建、不得进入 `dist/`**。
- **红线**：`.local-fonts/` 与 `F:\Fonts` 等本机路径**不得**出现在 `astro.config.mjs`、`src/`、`public/` 或任何构建产物中；公开文档（含本文件）不得收录个人字体清单。

## 4. 回退策略（强制）

- 任何生产字体栈都必须以**系统回退链**收尾，且必须包含**系统中文**与通用族兜底（`sans-serif` / `serif` / `monospace`）。
- 推荐排序：`<拉丁 / 展示字体变量>`, `<Zhuque / LXGW / Ark Pixel 等 CJK 字体变量>`,（中文）`'PingFang SC', 'Microsoft YaHei'`,（日文，如需）`'Hiragino Sans', 'Yu Gothic UI'`, 通用族兜底。
- 罗马字角色只有在整条栈不承诺 CJK 时才可省略 core-cjk 变量；任何 `font` / `font-family` 声明都不能只写一个 `var(--font-*)`。
- **禁止把系统中文字体放进 Astro 字体 registration 的 fallback 数组**：它会封进变量并抢在后续 CJK 变量之前。系统链只写在设计 CSS。
- `Preview.astro` 与正式页共享同一门禁：预览中的字体变量同样需要显式 fallback 与正确的 CJK 顺序。
- 六项记录里的第 4、6 项必须写明：简体中文 / 日文 / 英文各自的实际覆盖（以清单数字为准），缺哪类、回退到哪类系统字体、顺序如何。
- 无 JS、断网或字体加载失败时版式必须仍可读（延续站点既有验收：SPEC §13-10）。

## 5. 与验收、文档的关系

- 字体改动 = 设计页改动：完成后按 `.agents/skills/design-page-verify/SKILL.md` 执行验证流程；生产字体相关结论更新到 `docs/verification/`。
- 规则变更 → `docs/rules/visual-language.md`「字体（Typography & Fonts）」节；**流程与工具契约变更 → 本文件**；长期决策 → `docs/adr/`。
- 分工：本文件只写**流程与规则**；本机字体清单、候选与目检记录留在 `.local-fonts/`（如 `font-candidates.md`）。
