# 本地字体库隔离：候选在本地，生产走许可闸门与既有注册管线

> **生产分发层修订**：本地工作台与许可闸门仍然有效；非 npm 生产字体的分发已由 [ADR 0012](./0012-external-font-catalog-and-cjk-shards.md) 改为外部锁定目录、完整 CJK 分片与 primary-face Astro 变量。本文中“vendored 字体资产”只保留为当时决策背景。

SenrenBanka 新增拟物主题需要大量非标准字体，本机存在一个经目录联接统一的个人字体库（数百个 face）。我们决定：**本地字体库只用于发现与预览**（存放于被忽略的 `.local-fonts/`，不入库、不进构建）；字体进入生产管线必须通过**许可闸门**（确认允许网站嵌入与再分发），并继续按 `astro.config.mjs` 的 `fonts` 注册机制（npm provider、构建期自托管）接入；**生产配置与公开文档不得指向本机路径**。

## 背景

- 二期扩充与新增拟物主题（打印机 / 档案 / 仪表 / 复古印刷 / 像素 / 手写等）对字体的需求远超当前生产字体集（6 个 `@fontsource-variable` 包），本机个人字体库是最重要的候选来源。
- 项目硬约束不变：**构建期自托管、运行时零第三方字体请求**；`fork 后零配置`（GH Actions / CF Pages / Vercel 不携带本机环境）；字体族的每次新增都需要可离线复现的注册（SPEC §3.2-13）。
- 字体许可现实：个人字体库同时包含**已声明许可**、**未声明许可**与**明确非商用**的字体；把文件直接复制入库/配置指向本机都会把许可与可移植性问题引入仓库。

## 决策与依据

**两层分界**：

| 层 | 位置 | 职责 | 可否入库 |
|---|---|---|---|
| 本地层（发现 / 预览） | `.local-fonts/`（目录联接字体库 + 扫描清单 + 样张工具） | 扫描识别、覆盖测量、样张目检、候选记录 | 否（`.gitignore` 已覆盖） |
| 生产层（正式字体资源） | `astro.config.mjs` `fonts` 注册（npm provider）经许可核实后 vendored 的字体资产 | 构建期自托管、页面按需加载 | 是 |

**支撑机制**（本次建立）：

- 扫描工具复用 Astro 字体工具链自带的 `fontkitten` / `fontace`（随 `npm ci` 安装，MIT），**零新增依赖**；覆盖统计为完整 cmap 映射（枚举 + 非零字形校验），不做名称推断。
- 选型流程写入 `docs/fonts/selection-guide.md`：先设计隐喻 → 本地候选 → **样张目检（真实文件渲染，不可跳过）** → 许可闸门 → 生产接线与六项记录。

## 考虑过的替代方案

| 方案 | 否决理由 |
|---|---|
| 把本机字体复制进仓库 / `src/assets/` 直接引用 | 许可无法核实的字体随开源仓库**再分发**即违规风险；仓库体积与 CI 时长上升；许可核实前的"半成品"会诱导后续误用。 |
| 生产配置直接指向 `F:\Fonts` 或 `.local-fonts/library/` | 本机路径不可移植，CI / 他人电脑构建立即失败，直接违反"fork 后零配置"。 |
| 只用系统字体栈（Tahoma / 宋体等），不引入任何生产字体 | 放弃版式可控性；跨平台渲染不一致；与既有"构建期自托管、离线可读"验收冲突。 |
| 按字体名 / 元数据直接分配主题字体（跳过样张） | 名称欺骗性已被实测证实（同名不同覆盖、含 `CJK/Japanese` 字样但与预期不符、集合内 face 命名与子族名不一致）；且拟物气质只能靠目检定案。 |

## 后果

- **正向**：选型可重复（扫描清单 + 样张工具 + 六项记录模板）；生产可移植（注册即代码，CI 零配置）；合规路径明确（许可闸门三层判据）。
- **代价**：每次新增字体多出"目检 + 记录 + 许可核实"步骤；本地候选与生产可用字体集天然不同步——本地发现到的字体**不自动等于**可上线字体。
- **边界**：许可判据以字体内嵌字段与厂商官方许可页面为准；`fsType` / 内嵌文本只作线索，"未声明 ≠ 不可用、已声明 ≠ 可直接嵌入或再分发"。未核实许可的字体只能停留在本地候选。
