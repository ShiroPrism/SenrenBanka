# 构建期字体分片裁剪：源字体保持完整，部署按最终文本取分片

SenrenBanka 在 `astro build` 之后新增 `fonts:prune` 步骤：按最终 `dist` 的文本逐页保留命中的 `@font-face` 规则，把保留规则外置为共享哈希 CSS，并删除全站无人引用的字体分片。源字体、字体目录锁、快照与分片集合保持不变；部署产物只带当前构建真正使用的分片。整个 `dist` 以 15 MiB 为硬上限。

## 背景

- 当前 `dist` 约 33.5 MB：字体 21.37 MB / 611 个分片，HTML 11.31 MB，其中 9.06 MB 是三种语言重复的内联 `@font-face` CSS。
- 全站可见文本只有 1,031 个不同码位；按 `unicode-range` 命中约 229 个分片、8.13 MB。绝大多数完整 cmap 分片从未被任何页面请求。
- 早先的站内用字子集要求开发者本机持有源字体并重新裁字；干净 clone 与 fork 无法重建。ADR 0012 因此改为外部目录的完整 core-cjk 分片。
- 外部字体目录现在已能按锁下载生产字体包；fork 用户的阻塞点消失，可以在构建期按自己的资料文本自动裁剪。
- 直接做字形级子集化会修改字体字节，触发 OFL Reserved Font Name 审查，并引入新的子集化工具、源字体下载、两遍构建与内容相关的字体哈希缓存失效。

## 决策

### 1. 源字体完整、部署裁剪

- catalog、lock、`fonts:prepare`、`src/fonts/generated.ts` 与 `.cache/fonts/` 继续保存和验证完整源家族与完整分片。`fonts:prune` 只读取最终产物，不打开、不改写、不重新子集化任何字体文件。
- 字体按**整分片**保留或删除：命中当前构建文本的分片保留，无人命中的分片删除。该操作不构成字体修改，因此不触发 OFL RFN 的修改条款。
- 新增 `Deployment shard set（部署分片集）` 概念：它是当前构建文本的派生产物，不是新的字体发行版本，也不改变 `Font coverage contract` 对源字体的承诺。

### 2. 逐页判定、全站保留

- `fonts:prune` 扫描每个 HTML（原始 HTML 文本 + 其链接的本地 CSS / JS，解码 HTML 实体与 CSS 转义），收集页面语料；语料有意过近似，覆盖属性值、内联 JSON、模板、JS 字符串与 CSS `content`。
- 每页只保留与该页语料相交的 `@font-face` 规则；无 `unicode-range` 的规则始终保留。规则删除后，页面可见文本必须逐字一致，否则中止且不删除字体。
- 字体文件按全站保留集合处理：任何页面仍需要的分片保留；删除范围固定为 `dist/_astro/fonts/`，路径解析拒绝 `..` 并强制落在 `dist` 内。

### 3. 字体 CSS 外置与共享

- 保留的 `@font-face` 规则写入 `dist/_astro/fonts-<hash>.css`，页面 `<head>` 用一条 `<link rel="stylesheet">` 引用；`--font-*` 变量与其他内联 CSS 原样保留。
- 字体族集合相同的页面（同一设计的多语言版本）复用同一个 CSS 包；包内是这些页面所需规则的并集。外置文件只含 `@font-face`，不聚合设计 CSS，不改变每套设计只加载自身样式文件的契约。
- 链接前缀从页面已有的字体 URL 推导（`/demo/_astro/fonts/x.woff2` → `/demo/_astro/`），不读配置、不写死 `/`。

### 4. 体积与审计门禁

- `dist` 全部文件字节之和超过 15 MiB（15,728,640 B）时构建失败；报错输出体积桶、字体统计、最大文件与 `.cache/fonts/prune-report.json` 路径。不得为提高余量放宽阈值。
- `fonts:audit` 改为校验部署集合：解析内联样式与链接本地 CSS 中的 `@font-face`；每个 URL 必须存在；`dist/_astro/fonts/` 不得有孤儿分片；源字体覆盖的 CJK 字符若未被该页部署规则覆盖即失败；源字体本身缺字仍只警告。
- 浏览器验证必须用普通页面排版产生的字体请求或 CDP 平台字体信息证明核心字体命中，不得用强制 `document.fonts.load()`。

### 5. 构建与 fork 流程

```text
fonts:prepare (从外部目录下载并验证锁定字体)
-> astro build
-> fonts:prune (生成部署分片集 + 外置字体 CSS + 体积门禁)
-> verify:html-only
-> fonts:audit (校验部署集合)
```

fork 用户不需要本地字体、Python 字体工具或字体子集化工具；构建文本变化会自动重算部署分片集。

## 考虑过的替代方案

| 方案 | 否决理由 |
|---|---|
| 继续部署全部 core-cjk 分片 | 21.37 MB 字体 + 9 MB 重复内联 CSS；加语言只增不减，无法满足 15 MiB。 |
| 字形级子集化（Q18 B/C） | 体积更小，但修改字体字节、触发 RFN 审查、需要源字体与新工具链、构建两遍、内容变更导致字体哈希与缓存失效；相对分片裁剪的额外收益不足以抵消复杂度。 |
| 只外置字体 CSS、不裁剪分片 | 仍约 27 MB，达不到目标。 |
| 全站合并成一个字体 CSS 包 | 会把不同设计的字体规则聚合到所有页面，破坏每套设计只加载自身样式的隔离语义；按字体族集合分包已能跨语言共享。 |
| 恢复站内固定文本子集 | 与 ADR 0012 冲突；资料或语言变更后需要重裁，fork 无法保证覆盖。 |
| 系统字体替代自托管 CJK | 破坏设计字体契约与跨平台排版一致性。 |

## 后果

- 部署体积与文本规模相关，而不是与源字体 cmap 规模相关；当前实测 `dist` 14,520,742 B（13.85 MiB），字体 247 / 9,147,548 B。
- 页面只 link 自己需要的字体 CSS 包；同一设计的多语言版本共享一个包，减少重复 HTML 与缓存填充。
- 资料文本改变会改变部署分片集与字体 CSS 哈希；这是静态站点的正常重建行为，源码字体与锁不受影响。
- `fonts:prune` 成为构建的必要步骤；跳过它会让 `fonts:audit` 面对未裁剪的部署集合，体积门禁也不会执行。
- 审计从“源 cmap 覆盖”升级为“源 cmap 覆盖 + 部署文件存在 + 无孤儿”，裁剪缺陷不会被静默吞掉。

## 回滚

- 应用回滚：从 `package.json` 移除 `fonts:prune`，删除 `scripts/fonts/prune.mjs`、`scripts/fonts/lib/font-css.mjs`、`scripts/fonts/prune.test.mjs` 与审计改动，重新构建即可恢复完整分片产物。
- 不涉及 catalog、lock、`src/fonts/generated.ts` 或字体二进制的回滚；本决策没有修改它们。
- 若未来需要字形级子集化，应在新的 ADR 中重新评估许可、源字体、工具链与可复现性，而不是在本步骤上隐式扩展。
