# 根 AGENTS.md 索引化，规则正文归入 docs/rules

**Status:** accepted

项目级规则长期堆叠在根 `AGENTS.md`，到 2026-10-29 已达 26,568 字符（约 14k tokens），每次会话自动加载。多数任务只需要其中一小部分，关键红线反而被长文淹没。本次把“自动入口成本”与“规则正文体积”解耦。

## Decision

1. `docs/rules/` 是项目级规则的**唯一完整正文来源**。
2. 根 `AGENTS.md` 只保留：8 条不可延迟加载的硬门禁、按任务类型读取的路由表、规则正文索引、文档边界，以及 Trellis 托管区块。
3. 根文件不得复制规则长段落；每条硬门禁只写一句可判定陈述并链接正文。
4. 规则正文按主题拆为 7 个文件：数据与多语言、设计契约、共享操作菜单、视觉语言、无障碍与响应式、已知坑、构建与发布操作。
5. 根文件预算为 7,000 UTF-8 字符（含 Trellis 区块），由 `scripts/verify-agent-docs.mjs` 在 `npm run check` 中强制执行。
6. 历史 change-log 与归档任务保留当时引用，不回写；现行源码、文档、SPEC、skill 与活跃任务迁移到 `docs/rules/`。

## Considered Options

- **继续维护单文件**：自动加载成本随规则增长线性上升，且无法按任务裁剪；否决。
- **根与 docs 都保留完整正文**：会形成两份权威来源，迟早漂移；否决。
- **每个现有章节各建一个文件**：约 15 个文件，碎片化且读取路径不清晰；否决。
- **嵌套 `AGENTS.md`**：Codex 自动加载语义不保证，容易静默漏读；否决。
- **只拆文件、不加门禁**：拆完仍会重新膨胀；否决。

## Consequences

- 典型任务只需读根入口 + 2–4 个主题文件，不再无条件加载全部规则。
- 规则维护多一步“先改正文、再检查入口”，但消除了双正文。
- 新增链接与预算门禁，`npm run check` 会拒绝缺文件、断链、缺硬门禁、缺 Trellis 区块与超预算。
- 根文件不再适合承载完整解释；历史原因、实测细节与例外继续留在正文、ADR 或验证记录。
- 调整预算、拆分 / 合并主题文件、增删根硬门禁，均需同时修订本 ADR 与门禁常量。
