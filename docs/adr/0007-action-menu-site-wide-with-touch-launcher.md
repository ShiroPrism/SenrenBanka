# 操作菜单全站化：悬浮球入口、页面上下文与触屏可达

> **本 ADR 取代 [ADR 0004](./0004-context-menu-replaces-visible-switch.md) 的决定 2 与被否决项第 2 条**，并修订 [ADR 0003](./0003-differentiated-motion-enhancement.md) 的决定 4。0004 与 0003 本身保持不变（决策只追加不修改）。
>
> **2026-10-28 更正（ADR 0009）**：决策 2 所述“移动端无 JavaScript 时语言切换仍然可达、静态 DOM 本身就是回退”不成立——两份容器初始均带 `hidden`，悬浮球与菜单交互也依赖运行时，因此无 JS 时这些语言链接不可见、不可达。基础设施页继续由 `<noscript>` 回退；`html-only` 设计使用始终可见的原生语言链接。原文保留为当时的决策记录。

## 背景

ADR 0004 把设计切换入口定为「桌面鼠标环境的右键菜单」，并**明文否决**了移动端替代入口：触屏设备不提供菜单、不模拟长按、不加载菜单逻辑，设计页也不保留任何移动端替代入口。当时的代价是明确的——**语言切换随之仅桌面可达**，2026-10-12 由项目所有者裁定接受，换取的是消除 8 套设计重复排版语言切换器的成本。

v0.9.0 把语言切换并入菜单的语言二级菜单后，这个取舍的前提变了：**语言切换成了菜单的唯一入口**，触屏不可达不再只是"少一个便利功能"，而是移动端用户无法换语言。SPEC §7.5 当时为此预留了退路：「若后续需要移动端语言切换，应另加页面内入口而非改回逐设计排版」。本 ADR 执行的就是这条退路。

## 决策与依据

1. **单一菜单实现，两种容器形态**。菜单的数据、文案、动作处理与状态语义在所有输入环境完全共享；**只有容器形态与语言项呈现方式分叉**：
   - 桌面 `Context menu`：贴近光标定位，语言项收在二级子菜单；
   - 移动 `Action sheet`：底部动作面板，语言项**平铺**（触屏没有 hover 二级菜单的心智模型，用户不会"点开子菜单去看语言"，他会滑到列表底部）。

   选底部面板而非居中模态：375px 宽里二级菜单几乎无处安放（向左翻转就贴边）；而非全屏列表：无遮罩就没有"临时弹出"的语义，用户会以为发生了导航。

2. **两份 DOM 由 SSR 同时输出，运行时按输入能力摘除**。被摘下的那份用 `hidden`（同时移出无障碍树，不会被重复朗读）。代价是每个设计页多出约 40 行隐藏标记；收益是**移动端无 JavaScript 时语言切换仍然可达**——那份静态 DOM 本身就是回退，不需要额外写 `<noscript>` 语言列表。

3. **输入能力判定 = 媒体查询初判 + 运行时校正**。悬浮球初判用 `(any-pointer: coarse)`；一旦收到真实 `pointerdown` 的 `pointerType`（`touch` / `mouse`）即切换形态并记入会话级 `sessionStorage`。不用纯媒体查询，是因为 `(any-pointer: coarse)` 在**大屏一体机**这类主输入其实是鼠标的设备上会命中，会多出一个没人点的球遮挡内容。偏好存 `sessionStorage` 而非 `localStorage`：输入方式是设备会话属性，不该与主题偏好混在同一键空间，也绝不能污染 `storageKeyFor()`。

4. **引入 `Page context`（页面上下文）判别联合**，替代可空的 `currentId`。取值 `design` / `switcher` / `not-found`，由它决定身份条是否渲染、随机抽选是否排除当前、「切换设计…」是否隐藏、以及语言项目的标 URL。**不假设每页都存在"当前主题"**——切换页与 404 没有 `designId`，随机抽选必须走全池，绝不能去排除一个不存在的"当前主题"。

5. **随机主题在所有页面可用**（项目所有者裁定）。切换页上「切换设计…」是重复动作，因此在**构建期**就不渲染，而不是运行时隐藏。存储语义（`storageKey` / `{designId, expiresAt}` / `random`·`fixed` / `cacheHours` / `avoidImmediateRepeat`）与 `router-script.ts` 完全一致，且语言切换不重置主题偏好。

6. **接入所有有实际交互意义的页面**：8 套主题 × 3 语言、`/{locale}/designs/`、404。**四类"立即跳转"页不接**（`/`、`/{locale}/`、`/{design}/`、`/designs/`）——它们在 `<head>` 内同步跳转，停留不足一帧，挂菜单是自相矛盾的；它们自带的 `<noscript>` 链接列表本身就是回退。

7. **`manualSwitch` 只控制主题组**。菜单本体与语言分组在任何配置下都渲染；`manualSwitch: false` 时主题组整体不渲染、切换页不构建（404），但**语言切换与页面操作不受影响**。`contextMenu.enabled` 字段因此失去信息量，从配置与文档中删除。

8. **切换页与 404 的可见 `LanguageSwitcher` 保留但包进 `<noscript>`**。运行时只有共享菜单一个可见入口（不会出现两个可见语言入口），无 JS 时靠它回退。设计页不加（维持 v0.9.0 已裁定的取舍）。

9. **原生右键保留规则完全不变**：链接、图片、输入控件、可编辑区、已选中文字、触屏来源一律交还浏览器原生菜单，**不得对全页无条件 `preventDefault()`**。移动端不靠长按打开，也不拦截原生长按与文本选择。

10. **面板打开时锁背景滚动**：给 `<html>` 加 `overflow: hidden`（锁 `<html>` 本身不丢滚动位置，无需 `position: fixed` 技巧）+ 面板 `overscroll-behavior: contain`（防 iOS 从面板底部继续上滑时**穿透**到背景）。两者解决的是不同问题，缺一不可。

## 与 ADR 0003 的关系

ADR 0003 的决定 4 写的是「**不新增任何运行时 JavaScript / 依赖**」。该条的原始语境是**动效增强**（"不新增运行时"针对的是动效，不是菜单运行时）。但字面上它与本决策冲突，因此在此**正式修订**：该约束适用于**各设计的动效**，不适用于项目级 chrome 的菜单运行时。菜单运行时仍是唯一的 JS 依赖来源，且仍按能力门控动态加载（不静态 import）。

## 被否决的选项

- **居中模态卡片 / 全屏列表作为移动形态**：见决策 1。
- **悬浮球可拖拽**：需要持久化位置、边界回弹与键盘可达性处理，成本远超收益；右下角是 8 套设计都验证过"无横向溢出"的角落。
- **纯媒体查询决定悬浮球显隐**：见决策 3。
- **运行时用 JS 动态构建移动面板**（HTML 体积最小）：无 JS 时移动端完全没有入口，违背渐进增强。
- **在四类立即跳转页接菜单**：见决策 6。
- **`Page context` 用可空扁平字段**（`designId?` / `designName?`）：会让 `undefined` 同时表达三件事，丢失"此处无当前主题"的语义。

## 后果

- **正向**：移动端获得完整的语言切换与页面操作入口；切换页首次接入共享菜单（v0.5.0 起的现存缺口）；`storageKey` 不含 locale 的既有语义未受影响。
- **代价**：24 个设计页各多约 40 行隐藏 DOM；8 套设计页与切换页需接入两份容器形态；菜单组件与运行时规模约翻倍。
- **术语**：`Context menu` 降级为"共享操作菜单的桌面形态之一"，`Action menu` 为统称（见 `CONTEXT.md`）。
- **实测中修正的两个既有缺陷**（v0.10.0 一并修复）：
  1. 桌面态下菜单容器初始**未隐藏**（`applyMode` 误写 `root.hidden = touchMode`），浮层菜单常驻可见；
  2. `→` 键在"子菜单已展开但焦点仍在触发项"时被 `if (subOpen) return` 拦掉——而 `↑↓` 自动展开恰恰造成这个状态，导致键盘无法进入子菜单；且焦点进入子菜单后 `↑↓` 会循环主菜单项而非子菜单项。
- **易错点**：菜单运行时不得 `import` 任何 CSS（会触发 CSS 聚合陷阱）；两份 DOM 中被摘除的一方必须用 `hidden` 而非 `display: none` 类，后者不改变无障碍树语义。
