# 0.8.1（2026-10-12）修复：material3 宽屏首屏头像位置

## 成果

- **头像管线落地（本次修复的前置）**：`profile.yaml` 新增 `avatar` 字段 + 图片入库 `src/data/assets/TadokoroKoji.png`（302,730 B）；由数据层 `src/lib/site.ts` 的 `resolveAvatar()` 统一解析（本地 `ImageMetadata` / 外部 URL / `null`），各设计按自身取舍渲染、不自建头像管线。frost / kern / material3 三套渲染 `<img>`，其余设计按DESIGN.md 取舍未渲染。
  - 配置口径：`avatar` 只接受 `http(s)://` URL 或 `src/data/assets/` 下的文件名（可带可选 `assets/` 前缀）；写 `src/assets/xxx.png` 这类相对路径**不生效**。
  - provenance：示例占位资料（profile.yaml 头部已声明为虚拟人物，用于验证字体回退与排版），非真实个人信息。

## 修复

- **material3 首屏在宽屏下右侧恒定空出 288px**：`.m3-hero` 被 `max-width: 46rem`（736px）掐住，而下方分区 / 卡片网格通栏（1024px）。实测 1920 下 `main.right 1464` vs 首屏最右内容 `1176`；头像（112px）被迫退化为正文上方的装饰件，形成「明明右边大片空白却仍上下堆叠」的观感。
- **改 canonical 两窗格**：窄屏（compact / medium）维持「头像在正文之上」的单列堆叠；≥1024px 改 `grid-template-columns: minmax(0,1fr) auto`，文本为主窗格、头像为右侧支撑窗格（`clamp(11rem, 16vw, 14rem)`、`align-items: start`），并解除首屏的 `46rem` 限制。正文列宽改由 `.m3-title`（26ch）/ `.m3-bio`（60ch）自身承担。
- **断点取 1024 而非尺寸类的 840**：840 下主列仅 776px，减去头像与 48px 间隔后正文不足 550px，45px `display-medium` 标题被挤成 4 行，并排反而更差；1024 起主列 ≥960px，两窗格才成立。
- **缺省头像兜底**：`profile.avatar` 缺省时（`site.ts` 解析为 `null`、不渲染 `<img>`）由 `:not(:has(.m3-avatar))` 收回单列——否则 `auto` 列宽虽为 0 但 `column-gap` 仍生效，正文右缘会与下方分区差出一个间隔。
- `Page.astro` 新增 `.m3-hero-text` 布局包裹层（纯布局，DOM 顺序未变：头像仍为首个子元素，键盘 / 辅助技术顺序与视觉顺序一致）。

## 横向核查（避免只修一处）

- 对全部 8 套设计在 1920 宽下实测首屏右缘死白，确认 **material3 是唯一真正失衡者**：govuk 320px（无头像，正文 `66ch` 属 GOV.UK Measure 铁律）、kern 48px（骨架语言本就左对齐通栏）、frost 20px（720px 居中单列，空白对称）、terminal 41px、editorial 80px（本就3fr/2fr 两栏）、fast / oxide 0px。**其余设计不动**——按各自 DESIGN.md 的设计立场，改它们只会破坏规范。
