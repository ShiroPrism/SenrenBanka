# 0.9.0 — 三语言 i18n（zh-CN / ja / en）

## 成果

- **多语言数据层**：`src/data/profile.yaml` → `src/data/profiles/{zh-cn,ja,en}.yaml`（三份共用同一套 `profileSchema`，字段与顺序一一对应）。语言清单收拢到 `site.config.yaml` 的 `i18n.locales`（`code` / `path` / `label` / `title` / `description`），全局 `site.title` / `description` / `lang` 移除，不再维护两套矛盾默认值。
- **多语言路由**：同一 `Page.astro` 经 `injectRoute` 注册到每种语言的固定路径，产出 41 页（3 语言 × 8 设计 = 24 页设计页 + 3 语言入口 + 3 切换页 + 根入口 + 404 + 8 旧路径跳转 + 旧 `/designs/` 跳转）。语言由 `resolveLocale(model, Astro.url.pathname)` 在构建期从路径首段解析，页面不各自判断。
- **文案两层结构**：共享文案 `src/i18n/messages.ts`（右键菜单标签与 Toast、切换页、入口页、404、语言选择器辅助文本）+ 8 套设计各自的 `src/designs/<id>/messages.ts`（按各自视觉语言撰写，不统一表述）。缺文件或缺键在**构建期**报错。
- **语言切换入口（最终形态：右键菜单的语言二级菜单）**：语言项收进共享 `ContextMenu.astro` 的**二级菜单**（`.cm-lang`），语言名用各语言**自称**、逐项带 `hreflang` / `lang`、当前语言标 `aria-current="page"` 并附勾选标记；目标**保持同一主题 id**。**各设计不再单独渲染可见语言切换器，也不需要在自己的 `style.css` 中排版**——8 套设计合计移除约 **9.4 KB** 重复 CSS。
  - **采用二级菜单而非平铺**：初版把语言项平铺进主菜单，实测在语言数增多时菜单会长到超出视口而不可用（18 种语言 = 18 行）。改为二级菜单后，**主菜单高度与语言数量完全无关**。
  - 触发方式三选一：鼠标悬浮（120ms 延迟开 / 180–220ms 延迟关，避免横扫误触与斜向移动误关）、点击切换开合、键盘 `→` 进入。
  - 子菜单定位：默认贴右侧，放不下**翻转到左侧**；纵向对齐触发项并收敛进视口。
- **`manualSwitch` 语义细化**：菜单整体保持随 `manualSwitch` 开关，但新增 `designActionsEnabled` 只门控**主题切换项**（随机 / 切换设计…）。`manualSwitch: false` 时这两项不渲染，**菜单与语言分组照常渲染**，语言切换不受影响。
- 基础设施页（切换页 / 404）不使用右键菜单，保留共享 `LanguageSwitcher.astro` 的可见切换器（样式由 `InfraStyles.astro` 提供），并抽出 `languageSwitcherData()` helper 消除两处重复的对象字面量。
- **基础设施页本地化**：`ContextMenu.astro`（9 处）、`lib/context-menu.ts`（6 处运行时 Toast）、`InfraStyles.astro`（原 CSS `content: ' · 当前 / current'` 改为真实可本地化元素）、`SwitcherPage` / `index` / `404` 全部随语言切换。
- **SEO**：`HeadMeta` 支持 `alternates`；各语言默认主题页互指 `hreflang` + `x-default`；`noindex` 的非默认主题不标注 hreflang；canonical 含 locale 前缀与 base。

## 架构决策

- 新增 `docs/adr/0006-multilingual-static-routing.md`：**不启用 Astro 原生 `i18n`**，改用显式 `injectRoute` + 自解析 locale。实测原生 `i18n` 开关两种配置产物完全相同（37 页 `diff` 一致），唯一作用是让 `Astro.currentLocale` 有值（不配时为 `UNDEFINED`），零收益且多一层路由真相来源。
- **旧无前缀路径**（`/<design>/`、`/designs/`）保留为默认语言兼容入口，采用**明确声明的降级方案**：静态 meta refresh + `canonical` + `noindex, follow`。静态托管无法在代码内实现真 HTTP 301（属平台配置），此点已在 SPEC §7.3 写明。
- **主题偏好跨语言共享**：`storageKey` 不含 locale，切换语言不重置随机有效期，也不为每种语言形成互相覆盖的选择。
- **删除无意义页脚文案**（项目所有者裁定，2026-10-13）：fast / frost / govuk / kern / material3 的页脚原有英文 `built from a single profile`（oxide / terminal 本就没有），初版直译为「由同一份资料生成」——**中文读者无法从中获得任何信息**，属翻译引入的噪音。已连同整行一并移除，页脚只保留姓名（material3 另保留「Material 3 设计系统汇编」来源署名）。相关文案键从各 `messages.ts` 删除，无残留引用。
  -由此确立**翻译纪律**并写入 `AGENTS.md`：翻译只处理已有文案，**不得为"显得完整"而新增解释性 / 自我描述的句子**；原页面没有的，译文里也不该有；语义拿不准先问所有者，不要自行润色。
- **三处刻意不翻译**（按评审裁定，理由记入各设计 `messages.ts`）：govuk 的 OGL v3.0 法律署名、terminal 的 `session ends — 谢谢访问 / EOF` 终端收尾、oxide 的 `CONTACT`（6 个标签中唯一无中文对应的不对称项）；oxide / terminal / editorial 刻意的 `EN / 中文` 双语标识按设计语言保留。

## 修复

- **locale 前缀缺斜杠**：`renderRouterScript` 拼接目标时漏掉中间的 `/`，实测产出 `/zh-cnfrost/` 废路径；已修为 `base + localePrefix + '/' + id + '/'`，三个语言入口实测均正确。
- **`switcherHref` 缺尾斜杠**：右键菜单「切换设计…」曾指向 `/zh-cn/designs`（无尾斜杠，与其他目标不一致）；已统一。
- **`site.config.yaml` 整段注释导致构建失败**：`site:` 下全部注释时 yaml 解析为 `null`（非"缺失"），原 `.default({})` 无法兜底，报出无信息量的 `Expected type "object", received "object"`；改用 `z.preprocess((v) => v ?? {}, schema)`。
- **多语言资料条目 id 带目录前缀**：glob loader 对 `profiles/*.yaml` 产出 `profiles/zh-cn`，匹配 locale 需取 `id.split('/').pop()`。
- **语言切换链接触控命中区不足**：初版独立切换器在 375px 下实测仅 17–34px；先按各设计补 `@media (pointer: coarse)` 规则至 44px，最终形态并入右键菜单后该问题自然消失（菜单本身不在触屏呈现）。
- **二级菜单焦点飞出菜单**（实测踩坑并修复）：最初在 `openSubmenu()` 里就把 `activeMenu` 切到子菜单，导致「悬浮展开」或「`↑↓` 移到触发项」后再按一次 `↓` 就跳进子菜单，焦点**飞出菜单落到 BODY**。改为仅在焦点**真正进入**子菜单时（点击 / `→`）才切换 `activeMenu`。同时 `items()` 必须按当前层级取项，否则子菜单项会混进主菜单序列。
- **`enterSubmenu()` 的空值类型错误**：`submenu` 为 `HTMLElement | null`，赋值给 `activeMenu` 报 TS2345；补 `if (!submenu) return;` 守卫。

## 验证

- `npm run check`：**0 错误 / 0 警告**；`npm run build`：41 页通过。
- **CSS 隔离**：产物仍只有 **8 个** `Page.*.css`；同一设计的三语言页面引用**完全相同**的单个 CSS 文件；根入口 / 404 / 语言入口 / 切换页 / 旧跳转页**均不引用任何设计 CSS**。
- **24 页桌面 + 375px 触控全量实测**：`<html lang>` 正确、`aria-current="page"` 每页恰好 1 个、**0 console 错误**、**横向溢出 0**、触控命中区最小值 **44px**（全语言全设计）。
- **语言/主题正交性**：8 套设计逐一确认切换语言**保持同一主题 id**；实点击 `/zh-cn/oxide/` → English 落点 `/en/oxide/`。
- **`BASE_PATH=/demo`**：内部链接 / CSS / canonical / hreflang **全部带 `/demo`**，全站无遗漏前缀；`/demo/zh-cn/` 等仍正确解析为 `zh-CN`（部署 base 未被误判为语言）；右键菜单随机目标同样带 base 与 locale。
- **配置开关**：`manualSwitch: false` + `mode: fixed` 下切换页与旧 `/designs/` **均不构建**、右键菜单零标记，而**语言切换仍为 3 个链接可用**；测试后已恢复示例配置。
- **降级与无障碍**：reduced-motion / 无 `IntersectionObserver` / IO 抛错三种情形下隐藏元素均为 **0**、门控不写入；无 JS 时正文与语言链接均可用（内容 1872 字符、3 个语言链接）。
- **零视觉漂移**：移除各设计语言切换样式后，8 套 `style.css` 与 `HEAD` **逐字节一致**（仅末尾换行差异）——文案本地化与入口重构未改动任何设计规则。
- **18 语言扩展性实测**：向运行时注入 15 种额外语言（共 18 种）后，主菜单仍为 **8 项 / 374px**（与 3 语言时完全一致），子菜单 416px 且自身可滚动、完全落在视口内——证明"主菜单高度与语言数量无关"这一契约成立。测后已移除注入项与临时配置。
- **二级菜单键盘可达性实测**：`↑↓` 在主菜单 8 项间循环**不飞出菜单**；移到「语言」自动展开、移开自动收起；`→` 进入子菜单聚焦首项、`←` 返回触发项；实点击 `/ja/oxide/` 的 English 落点 `/en/oxide/`（`lang=en`）。
- **impeccable 检测器**：editorial / fast / kern / material3 / terminal **CLEAN**；frost（`bounce-easing` ×2）、govuk（`overused-font`）、oxide（`codex-grid-background`）为**改动前既有且已记录例外**（已用 `git show HEAD:` 版本对照确认非本次引入）。中间态的语言切换 CSS 曾触发 editorial / terminal 的 `design-system-font-size`，在并入菜单后随样式移除一并消失。

## 未测 / 限制

- **真正的 HTTP 301 未实现**：静态托管下由平台配置决定，不在代码内；当前为 meta refresh + canonical + noindex 的降级方案（SPEC §7.3 已写明）。
- **未做真实搜索引擎验证**：hreflang 与 canonical 的正确性仅经产物断言与浏览器实测，未经 Google/Bing 实际抓取验证。
- **语言自动检测未实现且为项目决策**：不按浏览器语言改写 URL，不使用 Cookie 语言检测（SPEC §7.3）。
- **样例资料为虚构角色**，三语内容为示例翻译，非真实人物资料；替换为自己的内容时需自行校对译文。
- **日文排版**已在 375px / 桌面实测无溢出，但未做专业日文校对（字体回退依赖各设计既有 fallback 栈）。
- **语言切换仅桌面可达（项目取舍，已裁定）**：右键菜单受 `(hover: hover) and (pointer: fine)` 门控，触屏设备不加载菜单运行时 → **移动端没有语言切换入口**。为消除 8 套设计重复排版而接受此代价；语言项本身是普通 `<a>`，无 JS 时菜单 DOM 仍存在。若后续需要移动端语言切换，应另加页面内入口而非改回逐设计排版。
- **terminal 的 `.sr-only` 未定义**（`DESIGN.md` 要求用 sr-only 标题，但任何 CSS 中都没有该类定义，导致 6 个双语分区标题实际可见）——属**改动前既存缺陷**，与 i18n 无关，本次未修（修复会改变 terminal 视觉），已记入 `docs/verification/terminal.md`。
