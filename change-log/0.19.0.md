# 0.19.0 — 构建期字体分片裁剪与字体 CSS 外置

2026-10-31

## 成果

- 新增构建步骤 `fonts:prune`（`node scripts/fonts/cli.mjs prune [--dist dist] [--dry-run]`），在 `astro build` 之后按**最终 dist 文本**逐页裁剪 `@font-face`：只保留与该页语料相交的 `unicode-range` 规则，无 `unicode-range` 的规则始终保留。
- 语料取自最终产物本身（HTML 原始文本 + 链接的本地 CSS / JS，解码 HTML 实体与 CSS 转义），因此属性值、内联 JSON、JS 字符串与 CSS `content` 都被覆盖；语料只做过近似，不会漏掉页面真正需要的分片。
- 保留的 `@font-face` 规则外置为共享哈希 CSS（`dist/_astro/fonts-<hash>.css`），页面 `<head>` 内以一条 `<link rel="stylesheet">` 引用，`--font-*` 变量与其他内联 CSS 原样保留。字体族集合相同的页面（同一设计的多语言版本）复用同一个包，包内是这些页面所需规则的并集。
- 字体文件按**全站保留集合**处理：任何页面仍需要的分片保留，无人引用的分片删除；删除范围固定为 `dist/_astro/fonts/`，路径解析带包含性校验并拒绝 `..`。
- 新增体积门禁：`dist` 全部文件字节和超过 **15 MiB**（15,728,640 B）时构建失败，报错含字体统计、桶统计、最大文件和报告路径；报告写入 `.cache/fonts/prune-report.json`（不含时间戳与机器路径）。幂等：已裁剪的 dist 直接 no-op 并复核外置链接存在。
- `fonts:audit` 改为校验**部署集合**：解析内联样式与链接的本地 CSS 中的 `@font-face`，任一 URL 必须落在 dist 内且文件存在（悬空即失败），`dist/_astro/fonts/` 下不得有无人引用的分片（孤儿即失败），源字体覆盖的 CJK 字符若未被该页部署规则覆盖则**失败**（裁剪掉必要分片属构建缺陷）；源字体本身缺字仍只警告。
- 新增共享解析层 `scripts/fonts/lib/font-css.mjs`（unicode-range / `@font-face` / 内联样式 / 链接资源 / 实体与转义解码 / 语料收集 / dist 资产解析）与 `scripts/fonts/prune.test.mjs`（13 项），`fonts.test.mjs` 增加审计反向 fixture（丢分片、悬空 URL、孤儿文件）。
- 新增 ADR 0013，记录「源字体保持完整、部署按构建文本裁剪」的取舍与被否决的字形级子集化方案。

## 修复

- 无功能修复。此版本不修改任何字体文件、字体目录锁、快照、生成注册或设计页面 / 设计与文案。
