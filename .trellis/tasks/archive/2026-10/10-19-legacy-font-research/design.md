# design.md — 旧设计字体审计与最小修复架构

## 1. 审计边界

本任务只处理字体选型指南建立前完成、仍处于 `enabled` 状态的九套设计：

`archive`、`editorial`、`fast`、`terminal`、`oxide`、`material3`、`kern`、`govuk`、`frost`。

不把指南后的七套拟物主题重新纳入审计；不重做页面布局、内容结构、动效或交互。切换页及其 `Preview.astro` 是成本与隔离的验证对象，不是本任务的视觉重做对象。

## 2. 核心原则

1. **字体是设计语言的角色系统，不是装饰库存。** 先明确标题、正文、数字/技术标记的职责，再判断现有字体是否失配。
2. **证据优先于审美主张。** 任何替换都要同时有真实字符覆盖、目标字号目检、许可与回退依据；仅“更艺术”“更专业”不构成理由。
3. **系统字体可以是正确选择。** `fast` / `govuk` / `editorial` 的系统声部若与设计隐喻和上游口径一致，应记录其合理性，而不是强行自托管。
4. **修复标准是接线断裂与可读性，不是字体数量。** 新增字族必须带来可说明的识别力或可读性收益，并计入切换页字体并集。
5. **预览与正式页共享令牌，不共享执行。** 预览只呈现视觉签名；正式页的完整 CSS、脚本、交互和字体装配不进入切换页。
6. **保持静态部署。** 不引入服务器渲染、运行时字体 CDN、截图服务或必须联网的预览机制。

## 4. 处置结论与候选判断

### 4.1 必须修复：`oxide`

**事实**

- `src/designs/oxide/style.css` 仍引用 `SuisseIntl` 与 `GT America Mono`。
- `src/designs/oxide/Page.astro` 没有 `<Font>`，`Preview.astro` 导出 `fonts: []`，`astro.config.mjs` 没有这两个族的注册。
- 浏览器中 `document.fonts` 为空，计算值只是保留字体字符串，实际渲染由系统字体兜底。

**决策**

- 规范中的双声部关系保留：**文字声部 + 技术等宽声部**。
- 优先复用生产池已有、许可已经核实、且已被其他设计使用的 **Geist Variable** 与 **Geist Mono Variable**：
  - `--font-geist` 承担正文、标题与可读文字；回退链必须含系统中文与通用无衬线。
  - `--font-geist-mono` 承担频道标签、编号、状态与技术标记；回退链必须含系统等宽。
- 不引入 SuisseIntl / GT America Mono 的未授权替代副本；不因为“更像规范”而新增不可许可字族。
- 复用 Geist 的直接成本收益：不新增字体包，不扩大切换页的字体族并集；Oxide 的预览与正式页可以共享同一字体框架变量。

**ASCII/块字符闸门**

在修改 Oxide 前，必须对目标字符集做真实文件覆盖检查，至少包括：

```text
▁▂▃▄▅▆▇█
└─
●
■
→
```

若 Geist Mono 不覆盖其中某些字符，实施必须采用以下之一并在验证记录中说明：

1. 在技术声部字体栈中加入明确的系统等宽/Unicode 回退，让这些装饰字符由系统字体承接；
2. 把关键装饰改为 CSS/SVG 绘制，避免依赖字体覆盖；

不得让关键字符静默换字形，也不得为了这些字符引入一个体积很大的新字体族。正文与可访问文本不依赖这些装饰字符。

### 4.2 复核后保留：`terminal`

- JetBrains Mono 已经通过 npm provider 注册，并由 `Page.astro` 的 `<Font>` 加载；实际请求约 40KB。
- 它同时承担标题、正文、命令与 ASCII 装饰，符合“单一等宽声部”的终端隐喻。
- VT323 / Share Tech Mono 缺少现有波形、框线或状态符号的覆盖，且 VT323 不适合作为 15px 正文。它们不能作为无条件的替换。
- 只有在真实样张证明 JetBrains Mono 在 15px 正文与现有字符集上明显不合格时，才进入替换流程；否则在 `DESIGN.md` 写明保留理由、候选淘汰理由与回退顺序。

### 4.3 复核后保留：`editorial`

- Fraunces 负责展示标题，Georgia 负责长文正文，系统无衬线只负责小号大写标签。
- 这是有意的“印刷声部”分工，不是缺少调研。Georgia 的系统可读性和宋体回退与暖纸、油墨的隐喻一致。
- 新增 IM Fell、Prociono 等衬线会扩大字体并集，但没有修复明确缺陷；除非样张在正文灰度、中文回退或标题气质上给出可复核收益，否则保留 Fraunces + Georgia + 系统标签。

### 4.4 保留并补记录

- `archive`：已有完整六项记录，复核字体接线与字符覆盖即可。
- `fast`：Segoe UI 系统栈与厂商快照一致，保持零字体请求。
- `material3`：Roboto Flex 与 M3 型阶匹配，接线正确。
- `kern`：Geist + Geist Mono 的双声部与网格仪表一致。
- `govuk`：GDS Transport 不可再分发，Arial 是上游明确回退，不应被“更有性格”替换。
- `frost`：SF Pro 不可内嵌，Inter 是已记录的可再分发替代。

## 5. 记录归属

| 来源类型 | 设计 | 写入位置 |
|---|---|---|
| 自产 / 第三方分析复刻 | `archive`、`editorial`、`terminal`、`kern`、`frost` | 各设计 `src/designs/<id>/DESIGN.md` 的字体章节 |
| 厂商快照 / 官方文档汇编 | `oxide`、`fast`、`material3`、`govuk` | `docs/designs/<id>/ADAPTATION.md` |

厂商来源的 `DESIGN.md` 是只读规范，**不得**为了补记录直接改写。若实现与快照存在偏差，只写 `ADAPTATION.md` 并在验证文档中互引。

## 6. 六项记录模板

每套设计必须用同一顺序回答：

1. **隐喻与特征**：页面模拟什么物件，字体需要表达什么。
2. **角色分配**：标题、正文、数字/技术标记分别使用什么字体。
3. **取舍理由**：为什么是这套字体，而不是其他候选；候选为何被排除。
4. **覆盖与回退**：简体中文、日文、英文的实际覆盖，缺字回退到哪里。
5. **工程属性**：字重、可变轴、资源体积、许可与再分发条件。
6. **缺失顺序**：目标字体加载失败时的完整回退链，必须包含系统中文与通用族。

记录应描述**当前实现**，不写未实施的候选清单；候选比较只保留足以解释决策的结论。不得把 `.local-fonts/` 路径、个人字体清单或未核验许可的文件写入公开文档、`src/`、`public/` 或生产配置。

## 7. 字体加载与切换页成本模型

### 7.1 正式页

- 字体注册仍在 `astro.config.mjs` 的 `fonts`，使用 npm 或 local provider，`remote: false`。
- 页面通过 `<Font cssVariable>` 引入实际用到的族；不 preload 预览字体。
- `style.css` 只用 `@theme inline` 建立设计别名，不复制字体文件。
- 回退链必须覆盖中文、日文（如需要）与通用族。

### 7.2 切换页

- `SwitcherPage.astro` 在页面 entrypoint 内 eager glob `Preview.astro`，这是唯一合法的预览聚合点。
- 每个 `Preview.astro` 导出真实的 `fonts` 数组；系统字体设计导出 `[]`。
- 切换页用 `Set` 按字体变量去重后声明一次，**不得**由预览组件各自声明 `<Font>`。
- 预览只渲染少量文字；CJK 子集允许按 `unicode-range` 惰性下载，但不得 preload。
- 0.14.0 基线：CSS 51,963 B、HTML 89,379 B、82 个 `@font-face`、38 个生成族名、每语言运行时 22 个唯一 WOFF2、0 preload。

### 7.3 成本判定

| 变更 | 允许条件 | 不允许的做法 |
|---|---|---|
| 复用已有族 | 现有注册、许可与覆盖已核实 | 为预览重复注册同族 |
| 新增族 | 有明显设计收益，且有体积/请求记录 | 只因“更像艺术字体”新增 |
| 新增 CJK 字体 | 已有子集与覆盖策略 | 为少数字符整包引入 8MB+ 字体 |
| 新增预览文字 | 能体现视觉签名 | 为凑长度加入无信息文案 |

本任务预期不新增字体包；若 Oxide 采用 Geist，切换页不会因该修复增加新的字体族。

## 8. 数据流与边界

```text
design.json / profiles / messages
              │
              ▼
        Page.astro ── <Font> ── style.css
              │                    │
              └──── tokens.css ────┘
                       │
                       ▼
                 Preview.astro
                       │  fonts: CssVariable[]
                       ▼
                SwitcherPage.astro
                （按族去重，一次声明）
```

- `PreviewProps` 只传 locale、姓名、headline、location、links；不传完整 profile，也不建立对 `Page.astro` 或 `style.css` 的导入边。
- `tokens.css` 只承载设计令牌，作用域限定在正式页和预览的命名空间类；不得出现 `:root`。
- `Preview.astro` 不声明 `<Font>`，不 import `style.css`，不含可聚焦元素；调用方将其包在装饰性 `aria-hidden` 容器内。
- 字体族集合只由页面 entrypoint 收集；不把预览注册进共享模块的 glob。

## 9. 规模与 114 套设计

当前 16 套预览的成本主要来自 CSS 体积、DOM 节点与字体声明数，而不是网络请求数。按 0.14.0 约 3.25KB CSS / 5.6KB HTML 每套线性外推，114 套约为 370KB CSS / 637KB HTML，已经值得监控但不构成立即引入复杂机制的充分理由。

本任务采用的规模策略：

1. **不再增加通用预览模板**；每套预览保持设计私有、轻量、只表达视觉签名。
2. **不新增字族时优先复用**；新增族必须单独记录边际成本。
3. 在设计数量显著超过当前规模、且实测出现首屏渲染或滚动卡顿时，再评估：
   - `content-visibility: auto` 作为零 JS 的离屏渲染优化；
   - 按视觉族/来源分类或分页；
   - 按需加载。

本轮不实施分页、搜索、筛选或运行时服务器方案；这些机制在 16 套规模下增加维护复杂度而没有明确收益。

## 10. 关键风险与对策

| 风险 | 后果 | 对策 / 回滚 |
|---|---|---|
| Oxide 仅改 CSS 字体名 | 仍然静默回退，问题未解决 | 同时检查 `astro.config`、`Page.astro`、`document.fonts` 与实际网络请求 |
| Geist Mono 缺少块字符 | 波形/框线被系统字体静默替换 | 实施前做字符覆盖检查；必要时明确系统回退或改装饰实现 |
| 预览 import 正式页 CSS | 切换页带入 preflight、整页规则和交互依赖 | 保持 `Preview.astro` 自包含；构建产物断言隔离 |
| 预览声明 `<Font>` | `@font-face` 随预览数量膨胀 | 只导出 `fonts` 数组，由切换页统一去重声明 |
| 新增字族无预算 | 切换页字体并集与请求数上升 | 每新增族记录体积、许可、覆盖与边际收益 |
| 修改厂商 `DESIGN.md` | 违反只读快照契约 | 记录只写 `ADAPTATION.md`；评审检查 diff |
| 记录只有审美判断 | 后续无法复核，重复调研 | 统一六项模板，覆盖、许可、体积、回退必须可证据化 |
| BASE_PATH 或静态部署回归 | 字体/预览 URL 在子路径失效 | 构建时跑 `BASE_PATH` 检查，确保无第三方字体域名 |

## 11. 实施边界与回滚点

- **基线点**：实施前记录九套正式页的字体接线、实际请求、切换页 CSS/HTML/字体计数与构建页数。
- **Oxide 点**：只修改字体注册、页面 `<Font>`、`style.css` 字体栈和必要的记录；若视觉或字符覆盖不合格，回滚该设计而不影响其他八套。
- **记录点**：每套记录独立提交/回滚；厂商 `DESIGN.md` 不进入修改集。
- **预览验证点**：若某预览新增样式造成泄漏或字体成本超预算，删除该预览的改动即可回到色点回退形态。
- **文档点**：验证记录、共享成本表与 change-log 最后统一收口；任何数值以实际构建和浏览器观测为准。
