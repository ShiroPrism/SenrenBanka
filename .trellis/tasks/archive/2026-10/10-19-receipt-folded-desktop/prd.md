# receipt 桌面折叠双栏重构

## Goal

把 receipt 桌面页从「三份窄票并排、页面横向滚动」改为「一张当前语言宽票、内部折叠双栏」，
消除桌面端内容重复与左右空旷；<1024px 继续展示一张单栏票，移动端阅读与交互不退化。

## Background

- 当前桌面 ≥1024px 渲染全部语言三联（`loadDesignStrips`），每联 480px；1440 视口总宽约 1624px，
  需要窗口横向滚动，第三联初始不可见。
- 用户已明确选择方案 B：桌面只显示当前语言，一张宽票内部分两栏；不再同屏展示其他语言。
- 语言切换仍由共享操作菜单负责，设计页不新增切换控件。
- 当前工作树干净，receipt 相关实现与验证记录均可直接修改。

## Requirements

### R1 · 数据与页面结构

- `Page.astro` 改用 `loadDesignView('receipt', Astro.url.pathname)`，只渲染当前语言的一份完整票据。
- 删除三份票据同时输出、`is-primary` 分支与语言后缀 id 的运行时必要性；保留当前语言 `lang` 与可访问名称。
- `contextMenu`、`HeadMeta`、`Reveal`、字体与共享菜单接入保持不变。
- 页面不得自行解析语言、不得硬编码内部链接。

### R2 · 桌面折叠双栏

- 仅在桌面宽屏（建议 `min-width: 1024px`，以实际内容宽度验证后定稿）启用宽票：
  顶部品牌 / 姓名 / headline / bio 横跨整张纸；正文其余分区分配到左右两栏。
- 纸张在 1440 视口下视觉宽度约 `68–72rem`，左右台面留白约 `9–12%`，
  不出现页面级横向滚动，也不再靠重复票据填满宽度。
- 双栏按内容自然高度平衡；分隔使用票据语言：一道折痕 / 压线，不得引入卡片、圆角或纸内投影。
- 分栏后正文行宽保持在约 40–50ch；不可因纸张变宽出现长行。
- 顶部撕边、底部撕边、红章、条码、页脚仍作为一张完整纸面的收尾，不拆成两个独立面板。
- 纸张宽度、栏宽与间距使用容器查询或明确断点，避免 `vw` 假宽；1024px 下不得挤压到不可读。

### R3 · 单栏与移动端

- `<1024px` 显示当前语言的一张单栏票，阅读顺序完整、无横向溢出。
- 375px 触控环境下保留既有可读字号、链接命中高度与纸张内边距；双栏专属装饰隐藏。
- 桌面双栏到单栏只发生一次结构切换，不出现第三档半折叠布局。

### R4 · 设计与文档同步

- 更新 `src/designs/receipt/DESIGN.md`：把 Triplicate Rule 改为折叠双栏规则，
  明确结构、断点、折痕、栏宽、阅读顺序与动效在双栏下的表现。
- 更新 `docs/verification/receipt.md` 为当前真实验证结果，删除过期的三联断言。
- `messages.ts` 中若 `railTitle` 仅服务于旧三联说明，应移除或改为当前结构实际使用的文案；
  不得留下无用键或三语不一致。
- 预览 `Preview.astro` 继续只表现单联视觉签名，不要求复制正式页双栏。

### R5 · 可访问性与动效

- 标题层级仍为一份 `h1` 加各分区 `h2`，无跳级；每个分区有可访问名称。
- 双栏只改变视觉位置，DOM 阅读顺序必须自然：屏幕阅读器按姓名、简介、明细、订单、纪录、技能、结账的顺序读到。
- 序号、URL、引导线、条码、折痕、图章等装饰 `aria-hidden`，链接可访问名不受影响。
- 保留共享 `Reveal`：首屏印刷、滚动显现、跳转兜底、reduced-motion / 无 JS / 无 IO / IO 抛错均内容可见。
- 分栏后的首次显现不得出现长时间空白；核心内容仍在秒级内可见。

### R6 · 验证

- `npm run build` 通过（含 `astro check`，0 错误 / 0 警告）。
- `impeccable` 检测器对 `src/designs/receipt` 零发现，或全部为已记录例外。
- 桌面 1440 / 1024 / 1000 断点实测：无页面横向滚动、双栏只在桌面出现、字段完整。
- 375×812 触控仿真：无横向溢出，共享菜单可开合，链接命中高度达标。
- 三语言页面齐备且 `<html lang>`、robots、canonical、语言菜单目标正确。
- CSS 隔离仍成立：本页只链接自身 CSS，不混入其他设计样式，dist 无第三方运行时资源。
- 对比度沿用或重新实测，淡墨 / 纸张组合不低于既有结论。

## Acceptance Criteria

- [ ] AC1 桌面 1440 视口只渲染一张当前语言票据，`documentElement.scrollWidth <= innerWidth + 1`。
- [ ] AC2 桌面页面呈一张宽票双栏结构，顶部信息横跨，正文两栏，折痕可见但无卡片 / 纸内投影。
- [ ] AC3 1440 下纸张左右台面留白既不空旷也不贴边，实测后记入验证记录。
- [ ] AC4 1024px 宽票仍为双栏且正文可读；1000px 回到单栏，无中间态。
- [ ] AC5 375×812 触控仿真：单栏、无横向溢出、核心链接命中高度 ≥40px（目标 44px）。
- [ ] AC6 DOM 中恰 1 个 `h1`；分区标题无跳级，所有 section 有可访问名称。
- [ ] AC7 修改前记录当前语言切换落点；修改后验证语言菜单目标仍保持 receipt 主题。
- [ ] AC8 构建、检测器、CSS 隔离、字体与共享菜单检查通过。
- [ ] AC9 `DESIGN.md` 与 `docs/verification/receipt.md` 已同步为折叠双栏的当前事实。
- [ ] AC10 工作树仅包含本任务相关改动，验证记录可复核。

## Out of Scope

- 不修改共享操作菜单、路由、数据 schema 或其他设计。
- 不新增语言切换器、不改为动态多语言路由。
- 不改字体家族与字体资产；不新增图片或图标库。
- 不改变默认设计、随机主题语义、SEO 策略。
- 不实现横向滑动、轮播、自动滚动或 JS 驱动折叠交互。

## Risks

- 若把顶部也放进分栏容器，会破坏一张完整票据的阅读叙事；顶部必须显式横跨。
- 英文版本文字最长，1024px 下两栏可能过窄；需以最长语言实测后再定断点或栏宽。
- 折痕若使用渐变或阴影过重，会违反“纸内零投影”；应使用极细压线 / 低对比纸色差。
- 删除 `loadDesignStrips` 后，若其他文档仍描述 receipt 为多语言同屏，会留下过期引用。
